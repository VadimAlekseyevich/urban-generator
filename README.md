# Urban Generator

Веб-сервис для ВКР по процедурной генерации городской застройки с учётом пространственных, инфраструктурных и демографических ограничений.

По подготовленной карте территории сервис должен продолжать существующие улицы, размещать жилые дома и школы, рассчитывать прирост населения и показывать дефицит доступных школьных мест. Первый выпуск рассчитан на локальную демонстрацию в браузере.

**Текущий этап — развитие локального MVP.** Выпуск v1.0.0 остаётся на ручной приёмке. В интерфейсе можно открыть демо, свой TIFF, GeoJSON или локальный OSM PBF, задать прирост, этажность, шаг улиц и seed и сгенерировать улицы и дома. Крупная карта переключает исходник и проект в одном масштабе: доступны зум, перемещение, слои, общий вид и линейка. Щелчок по дому или школе открывает данные завершённого расчёта; новые улицы красные, дома зелёные. Выводятся цель, фактическое население, отклонение, недобор и причина остановки. Новые школы отмечены фиолетовым и номером; доступны бюджет, вместимость, сетевой порог, покрытие спроса и причины дефицита. Доступны проверенный экспорт и сравнение A/B. [Дизайн-документ и план семи версий до MVP](docs/DESIGN.md) содержит легенду TIFF и GeoTIFF, алгоритмы, стек, недельный календарь и контрольные примеры.

Собственный участок можно загрузить как [GeoJSON с ролями объектов](docs/GEOJSON.md) прямо в приложении или как подготовленный TIFF/GeoTIFF с кодами классов из §2 дизайн-документа. MVP рассчитан на выбранный фрагмент города до 256×256 ячеек при шаге 5–10 м; геопривязка сохраняется. Автоматическое распознавание классов из снимка и обработка больших городских карт относятся к дальнейшему развитию. Локальный OpenStreetMap PBF можно открыть прямо из приложения по пути на диске: [инструкция, кэш и отдельная CLI-команда](docs/OSM_IMPORT.md).

## Установка

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/getting-started/installation/). Получи рабочую копию и установи зависимости:

```bash
git clone https://github.com/VadimAlekseyevich/urban-generator.git
cd urban-generator
uv sync --frozen
```

Команда создаёт `.venv` и устанавливает зависимости из `uv.lock`, включая pytest. Версия Python задана в `.python-version`, поддерживаемый диапазон — в `pyproject.toml`. Для первой установки нужен доступ к сети. Если Python 3.12 отсутствует, uv может скачать его автоматически.

## Запуск

```bash
uv run --offline --frozen streamlit run app.py --server.address=127.0.0.1 --browser.gatherUsageStats=false
```

Открой <http://localhost:8501>. По умолчанию видны демотерритория, её легенда и площади. Сервер и приложение работают в одном локальном Python-процессе. Остановка — `Ctrl+C` в терминале.

Для первого импорта PBF запусти с дополнительным пакетом:

```bash
uv run --frozen --with osmium==4.3.2 streamlit run app.py
```

Выбери «OSM PBF», вставь полный путь к файлу, задай центр, размер и шаг,
нажми «Открыть участок OSM». Проверь карту, подтверди легенду и масштаб,
затем сгенерируй проект. Повторное окно переиспользуется из дискового кэша;
ошибка нового импорта сохраняет прежний успешный отчёт.

   Измени бюджет школ на 0 и снова нажми «Сгенерировать».
   В B население и дороги не изменятся, обслуживание 0, дефицит 76.
   Сравнение покажет разность B − A: население 0, обслужено −72.
4. Скачай «Скачать ZIP текущего проекта» (B), «Скачать ZIP варианта A»
   и «Скачать comparison.csv». Распакуй оба ZIP: открой result.tif в
   QGIS или Rasterio, metrics.json и buildings.csv в редакторе/табличной
   программе. Сверь 19 ID домов, сумму жителей 608, спрос 76 и разные
   значения обслуживания. CRS и affine-transform сохраняются.
5. После выгрузки верни бюджет 1 и задай цель 20000, остальные параметры
   оставь прежними. Нажми «Сгенерировать»: ожидается 619 домов,

## Проверка

В форме доступен [демографический профиль](docs/DEMOGRAPHY.md): площадь на
человека, полезная доля, доля школьников и источник. Дефолтный профиль
сохраняет прежний результат демо; варианты A/B содержат свои коэффициенты.

В ZIP доступны [пространственные объекты для GIS](docs/GIS_EXPORT.md):
`project.geojson` в WGS84 для геопривязанного входа или `project-local-wkt.csv`
в локальных метрах. `objects.csv` связывает геометрию, дома и школы по
`object_id`. Улицы выгружаются как полигоны ячеек, дома — как пятна.

Можно загрузить [отдельную границу освоения](docs/DEVELOPMENT_BOUNDARY.md):
новые объекты появятся только внутри неё, существующие дороги снаружи
сохранятся. Для демо есть `examples/development-boundary.geojson`.

```bash
uv run pytest -q
```

Тесты Streamlit AppTest проверяют загрузку файлов, подтверждения, генерацию улиц и домов, повтор с seed 42, изменение параметров, сохранение завершённого запуска и сброс проекта при изменении входа. Проверяются совпадение прироста с суммой жителей домов, недобор и причина остановки при недостижимой цели, цвета PNG и сохранность исходных объектов, сравнение бюджета школ, вместимость, сетевой порог, причины дефицита и нулевой спрос. Сквозная репетиция проверяет запуск локального HTTP-сервера, действия через AppTest и содержимое файлов; настоящий браузер и время показа на ноутбуке остаются ручной приёмкой (см. docs/DEMO_CHECK.md).

## Модели вычислительного ядра

`urban/model.py` импортируется без запуска интерфейса. В нём определены общая легенда `ClassCode`, фиксированные коэффициенты из §3, `CoordinateMode`, `Terrain` и `Scenario`.

`Scenario()` задаёт демопараметры: 600 жителей, 3 этажа, шаг улиц 8 ячеек, одну школу на 80 мест, путь 400 м и seed 42. У численных полей `Scenario` диапазоны и единицы доступны через `dataclasses.fields(Scenario)` в `metadata` (`min`, `max`, `unit`). У коэффициентов профиля — через `fields(DemographicProfile)`; источник/заметка является текстовым полем. Счётчики и seed принимают целые числа; предельный путь допускает дробные метры. Некорректные значения вызывают `ValueError`.

`Terrain` хранит исходные `classes`, булеву `valid_mask` (True — внутри исследования), `pixel_size_m`, `coordinate_mode`, `crs`, `transform` и `input_sha256` — SHA-256 байтов входного файла. Массивы копируются и защищаются от записи. Маска объединяется с кодом 255, исключённые ячейки получают 255. В локальном режиме передаются `crs=None`, `transform=None`: модель строит привязку с началом (0, 0) в левом нижнем углу. Геопривязанный режим принимает Rasterio CRS и Affine и сохраняет их.

## Чтение TIFF/GeoTIFF через ядро

```python
from pathlib import Path
from urban.io import read_terrain

terrain = read_terrain(Path("examples/demo.tif").read_bytes())
```

Для обычного TIFF без привязки передай `local_scale=10` — подтверждённый шаг в метрах. Если привязка частичная или её нужно отбросить, дополнительно требуется явный `discard_georeferencing=True`. Исходный SHA-256 сохраняется и при выборе локального режима.

Загрузчик принимает один целочисленный канал, до 256×256 ячеек и до 8 МиБ файла. Размеры, канал, тип, NoData и геопривязка проверяются до чтения пикселей. В метрическом режиме сохраняется квадратная сетка с шагом 5–10 м без поворота. Внутренняя маска TIFF, объявленный NoData и код 255 объединяются; коды проверяются внутри полученной маски. Объявление NoData равным 0–3 запрещено. Исходная дорога обязательна, а отсутствие свободной земли допустимо.

Ошибки вызывают `TerrainReadError` (подкласс `ValueError`) с причиной и подсказкой на русском. Демо и свой TIFF в интерфейсе используют этот загрузчик. GeoJSON преобразуется в ту же модель Terrain через urban.vector_import.read_geojson. Текущая валидная территория хранится в `session_state.terrain`; `terrain_ready` становится True после необходимых подтверждений и сбрасывается при изменении входа или ошибке. Предпросмотр и площади строятся функциями `urban.report`, исходные массивы сохраняются.

## Пригодность территории через ядро

```python
from pathlib import Path
from urban.io import read_terrain
from urban.generate import calculate_suitability

terrain = read_terrain(Path("examples/demo.tif").read_bytes())
suitability = calculate_suitability(terrain)
```

`Suitability` содержит `free_mask`, `road_distance_m`, `barrier_distance_m` и `scores` на исходной сетке. Свободны только ячейки класса 0 внутри маски. Расстояния евклидовы и измеряются между центрами ячеек в метрах. Для запретов учитываются класс 1, NoData и внешняя рамка; от центра граничной ячейки до ближайшего центра рамки — один шаг растра. Существующая застройка исключена из кандидатов, но не влияет на расстояние до запретов.

Балл свободной ячейки: `S = 0.7 * max(0, 1 - d/300) + 0.3 * min(1, b/50)`. Здесь d — расстояние до ближайшей исходной дороги, b — до запрета или рамки. Коэффициенты определены в `urban.model`. Вне свободной маски `scores` равен `-inf`, поэтому такие ячейки нельзя выбирать при ранжировании. Возвращаемые массивы защищены от записи; исходные классы и маска не меняются. Эта стадия не использует seed и автоматически выполняется перед ростом улиц.

## Рост улиц через ядро

```python
from pathlib import Path
from urban.io import read_terrain
from urban.model import Scenario
from urban.generate import generate_roads

terrain = read_terrain(Path("examples/demo.tif").read_bytes())
roads = generate_roads(terrain, Scenario(seed=42, street_spacing_cells=8))
```

`RoadNetwork` содержит отдельную булеву маску `new_roads`, общий слой `road_mask`, смещения осей `axis_offsets` (строка, столбец) и ранее вычисленную `suitability` для следующих стадий. Смещения выбираются локальным PCG64 из seed. Оси проходят по строкам или столбцам с заданным остатком от деления на шаг улиц и разрешены только на свободной земле.

Четырёхсвязное распространение начинается сразу из всех исходных дорожных ячеек. Оси без пути к старой дороге остаются пустыми; диагональное касание не создаёт связь. Вода, NoData и существующие здания исключены. Новые улицы не заменяют исходный растр, возвращаемые маски защищены от записи. Результат зависит только от территории, шага улиц и seed; бюджет школ, население и этажность его не меняют.

Форма использует `generate_buildings`, который вызывает тот же `generate_roads`. В `session_state.building_plan` сохраняется единый `BuildingPlan` с территорией, использованным сценарием и результатами стадий. `urban.report` собирает проект на копии исходного растра и рисует обе карты с общей палитрой и одинаковым увеличением. Передача изображений в PNG сохраняет точные цвета классов.

## Резерв школьных площадок через ядро

```python
from urban.generate import reserve_school_sites

reserve = reserve_school_sites(roads)
```

Функция принимает `RoadNetwork` после роста улиц и возвращает `SchoolReserve`: координаты `coordinates` в порядке «строка, столбец» и булеву `mask` для исключения площадок из будущего размещения домов. Сохраняется не больше 12 свободных одноклеточных площадок, соседних со старой или новой достигнутой дорогой по стороне. Сами дороги, застройка, вода и NoData исключены.

Строки делятся на 3 группы, столбцы — на 4. Если размер не кратен числу групп, первые группы получают по одной дополнительной ячейке (`np.array_split`). Пустые группы и сектора без допустимых кандидатов пропускаются. В каждом секторе выбирается максимум S, при равенстве — первая ячейка по строке и столбцу. На демо при seed 42 и шаге улиц 8 получается 9 площадок.

Бюджет и вместимость школ не передаются функции и не влияют на резерв. Исходные слои сохраняются, маска резерва защищена от записи. Резерв ещё не является открытой школой: его ячейки остаются свободными до последующего выбора и исключены из размещения домов. Открытые школы выбираются на следующей стадии, после размещения домов.

## Дома и прирост населения через ядро

После чтения территории:

```python
from urban.generate import generate_buildings
from urban.model import Scenario

plan = generate_buildings(terrain, Scenario(target_population=600, floors=3, seed=42))
```

Сквозной вызов рассчитывает улицы, резерв школ и дома. Для уже подготовленных стадий доступен `place_buildings(terrain, scenario, roads, reserve)`. Принимаются окна 2×2 свободных ячеек вне дорог, резерва и ранее размещённых домов. Хотя бы одна ячейка окна должна соседствовать с дорожной сетью по стороне. Приоритет — средний S; равные баллы упорядочиваются перестановкой PCG64(seed) исходного построчного списка и стабильной сортировкой по S. Занятость повторно проверяется перед каждым размещением.

`BuildingPlan` сохраняет входную территорию, сценарий, дороги, резерв, кортеж `buildings` и защищённый от записи слой `building_ids` (0 вне домов, последовательные ID от 1 внутри). В записи дома есть левый верхний угол, этажность, площадь пятна, население, спрос и первая по координатам пара входных ячеек `house_entry` / `road_entry`. Исходный растр не меняется.

Округление выполняется отдельно по каждому дому: `N = floor(4*h²*floors*0.8/30 + 0.5)`, `D = floor(0.12*N + 0.5)`. При шаге 10 м и трёх этажах это 400 м², 32 жителя и 4 школьника. `plan.population` и `plan.school_demand` суммируют округлённые значения. Нулевой спрос небольшого дома допустим.

После первого достижения цели размещение прекращается; превышение меньше населения одного дома. При исчерпании мест возвращается фактический результат, в том числе пустой. `stop_reason` равен `target_reached` или `candidates_exhausted`. На демо с дефолтными параметрами получается 19 домов, 608 жителей и спрос на 76 школьных мест. Интерфейс показывает дома и население из этого же результата. Для школ вызывается `calculate_school_services(plan)`, затем `validate_result(plan, allocation)` формирует проверенный отчёт.

## Демотерритория

Готовый `examples/demo.tif` содержит синтетический участок 96×96 ячеек с шагом 10 м в EPSG:32637. Река идёт от края до края; одна связная улица и пять исходных домов находятся на западном берегу. Восточный берег свободен и не имеет исходной дороги.

Повторное создание файла из корня репозитория:

```bash
uv run python -m examples.create_demo
```

[Описание схемы, легенды и проверок](examples/README.md). Данные создаются локально без сети и случайности; seed применяется к будущему сценарию застройки.


## Экспорт завершённого запуска из вычислительного ядра

```python
from pathlib import Path

from urban.generate import generate_buildings
from urban.io import read_terrain
from urban.model import Scenario
from urban.report import export_result_zip, validate_result
from urban.services import calculate_school_services

terrain = read_terrain(Path("examples/demo.tif").read_bytes())
plan = generate_buildings(terrain, Scenario())
report = validate_result(plan, calculate_school_services(plan))
Path("result.zip").write_bytes(export_result_zip(report))
```

В архиве три файла:

- `result.tif` — одноканальный растр UInt8 с кодами 0–6, NoData=255,
  цветовой таблицей и легендой. Для GeoTIFF сохраняются CRS и affine-transform.
  Локальный TIFF не получает фиктивную геопривязку; масштаб и начало
  координат в левом нижнем углу записаны в JSON.
- `metrics.json` — версии схемы и алгоритма (1), SHA-256 входа, параметры,
  коэффициенты модели, координатный режим, метрики с единицами, причины
  дефицита и сведения об открытых школах. Неопределённые проценты — null.
  Порядок коэффициентов affine: a, b, c, d, e, f (как в Rasterio).
- `buildings.csv` — UTF-8, заголовок даже без домов; ID, строка и столбец
  левого верхнего угла (от нуля), площадь, этажи, жители, спрос и обслуженные места.

Экспорт повторно проверяет согласованность отчёта; повреждённый результат
не выдаётся. Итоговый TIFF можно открыть в GIS, но это не исходная карта
для повторной генерации: входной контракт допускает только классы 0–3 и 255.
В интерфейсе скачивание и сравнение доступны в блоке «Экспорт и сравнение вариантов».


## Сравнение двух вариантов в интерфейсе

1. Открой демо, подтверди легенду и сгенерируй проект с бюджетом 1 школа.
2. В блоке «Экспорт и сравнение вариантов» нажми «Зафиксировать вариант A».
3. Измени только бюджет на 0 и нажми «Сгенерировать». Следующий успешный расчёт станет B.
4. Сверь карты, прирост населения и число обслуженных школьников. Дома и дороги
   не изменятся; при бюджете 0 обслуживание равно нулю.
5. Скачай ZIP текущего проекта (B), ZIP варианта A и comparison.csv.
   Значения A и B соответствуют завершённым запускам; delta = B − A,
   для процентов разность выражается в процентных пунктах. Неопределённые
   значения в CSV оставляются пустыми.
6. Для нового сравнения нажми «Сбросить сравнение» либо снова зафиксируй A.
   Изменение исходного файла или масштаба автоматически сбрасывает пару.

Изменение полей формы без запуска не меняет сохранённые отчёты. Ошибочный
повтор не заменяет последний успешный вариант и его архив. Сравнение хранится
только в текущей сессии Streamlit.


## Приёмка и вычислительный эксперимент

```bash
uv run python -m examples.run_experiment --output-dir experiment-results
```

Команда сохраняет paired.csv и experiment.json. Фактический прогон в CI,
методика и ограничения выводов приведены в [отчёте об эксперименте](docs/EXPERIMENT.md).


## Замеры производительности

```bash
uv run --frozen python -m examples.run_benchmark --output-dir benchmark-results
```

Один прогрев и пять повторов на картах 96×96 и 256×256. Результаты сохраняются
в timings.csv и benchmark.json. [Методика и фактические измерения CI](docs/BENCHMARK.md).
Пороговые времена подтверждены в CI; на ноутбуке защиты требуется повторить
замер.
