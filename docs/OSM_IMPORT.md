# Импорт локального OpenStreetMap PBF (v1.1, #45)

Импорт доступен из приложения и отдельной CLI-командой. Генератор получает
ту же метрическую Terrain по §2–4 DESIGN.md. Региональный PBF читается с
диска, не загружается в браузер и не отправляется в сеть. Дополнительный
Pyosmium нужен только для первого импорта окна; базовый uv.lock не изменён.
[Pyosmium](https://docs.osmcode.org/pyosmium/latest/) имеет колёса для Windows/Python 3.12.

## Открытие PBF в приложении (#52)

После установки базовых зависимостей запусти:

```powershell
uv run --frozen --with osmium==4.3.2 streamlit run app.py
```

Первый запуск требует сети для установки дополнительного пакета. Затем:

1. Выбери **OSM PBF**. В поле пути вставь полный путь к доступному локальному
   `.osm.pbf`, например `C:\Projects\data\city.osm.pbf`. Путь относится к
   компьютеру, на котором запущен Streamlit. Копировать сам регион в форму
   загрузки или заранее выполнять CLI-конвертацию не требуется.
2. Задай долготу и широту центра, сторону окна 1–256 ячеек и шаг 5–10 м.
   По умолчанию центр 39.72, 54.62 — пример, не проверенный участок.
   Окно 256×256 с шагом 10 м охватывает 2,56×2,56 км.
3. Нажми **«Открыть участок OSM»**. Статус показывает хеширование, сканирование
   и растеризацию. Процент сканирования неизвестен; на подготовке отношений
   сообщения могут долго не обновляться. Форма по умолчанию использует
   2 потока чтения; число потоков и индекс можно изменить до импорта.
4. Проверь открытую карту, фактический источник, охват, CRS и шаг. Подтверди
   легенду и масштаб, нажми **«Сгенерировать»** в форме застройки. Готовый
   вход можно скачать кнопкой **«Скачать подготовленный GeoTIFF»** и позднее
   открыть через «Свой TIFF». Атрибуция и SHA исходного PBF сохраняются.

Новые значения полей применяются только кнопкой открытия. До успешной
проверки нового окна остаётся прежняя территория с её отчётом, ZIP и
сравнением. При ошибке, отсутствии Pyosmium или прерывании они сохраняются.
Под картой всегда указаны фактические источник и охват открытой территории.
При успешном открытии другого окна сбрасываются подтверждения, расчёт и
сравнение. Повтор того же окна из кэша сохраняет завершённый расчёт.

Остановка средствами Streamlit срабатывает при ближайшем обновлении UI
из импортёра; во время первого прохода по отношениям она может задерживаться.
Это синхронный импорт в том же процессе, без отдельного сервиса и очереди.
Остановка всего сервера завершает сессию, как и при обычной генерации;
сохранение и возобновление проекта после перезапуска относится к #58.

## Повторное использование окна

Готовые окна находятся в `.urban-cache/osm/` рядом с кодом, исключены из Git.
Каждая запись — один ZIP с подготовленным TIFF и манифестом. Ключ учитывает
абсолютный путь PBF, потоковый SHA-256 содержимого, версию классификатора,
CRS, transform, сторону и шаг сетки, а также версию формата кэша. Смена
файла, даже с теми же именем, размером и временем изменения, проверяется по
хешу. Потоки чтения и индекс не меняют классификацию и не создают иной ключ.

Повторное открытие читает PBF последовательно для SHA-256, но не строит
индекс узлов и полигоны и не сканирует объекты OSM. Кэш работает и после
перезапуска приложения, даже без Pyosmium, если исходный PBF доступен.
При первом импорте исходник хешируется также внутри существующего
импортёра; хеши и состояние файла сопоставляются до публикации записи.
Региональный файл не сохраняется в кэше и не читается целиком в память.

Перед использованием записи проверяются состав ZIP, SHA TIFF, источник,
версия, параметры сетки, атрибуция, метаданные TIFF и сам Terrain. Неполная
или испорченная запись пересоздаётся. Временный файл закрывается и атомарно
заменяет готовую запись только после успешного импорта и проверки. Ошибка
или остановка не публикуют частичный результат; остатки `.tmp` после
аварийного завершения процесса не считаются готовыми окнами. Если нужно
освободить место, останови приложение и удали `.urban-cache/osm/`; исходные
PBF и скачанные результаты это не затронет. Автоматического вытеснения нет.

## Windows PowerShell

Из корня urban-generator после `git pull origin main` и `uv sync --frozen`:

```powershell
$pbf = "C:\путь\к\central-fed-district-latest.osm.pbf"
uv run --frozen --with osmium==4.3.2 python -m examples.import_osm "$pbf" --lon 39.72 --lat 54.62 --size 256 --pixel-size 10 --output ryazan.tif
uv run streamlit run app.py
```

Подставить **фактический путь** к файлу (например, перетащить файл в PowerShell).
Долгота 39.72, широта 54.62 — пример центра окна, не утверждение о пригодности
конкретного квартала. Для другого участка изменить координаты центра.
Размер 256×256 при 10 м/пиксель — окно 2,56×2,56 км; при 5 м — 1,28×1,28 км.
Открыть «Свой TIFF», выбрать ryazan.tif, проверить карту, подтвердить легенду,
запустить генерацию. Файл ryazan.osm.json (имя от выходного TIFF) содержит
происхождение данных, число геометрий, площади в ячейках и привязку.
Существующие выходные файлы не перезаписываются.

Первый запуск uv с дополнительной зависимостью требует интернета для её
установки. Сам импорт работает локально. Весь региональный файл сканируется,
индекс координат узлов и сборщик полигонов могут занять несколько ГБ RAM;
время и пиковая память на 835 МБ ещё не измерены. На 32 ГБ RAM стоит
сначала попробовать исходник, при нехватке памяти предварительно вырезать
регион меньшего размера утилитой osmium extract или использовать другой
поддерживаемый индекс (--index sparse_mem_array). Индекс по умолчанию flex_mem.
Выходной TIFF мал; исходный PBF не хранить в Git. Если в окне нет доступной
исходной дороги, импорт выдаст ошибку. Выбрать другой центр.

## Если региональный импорт долго выполняется (#47)

Теперь CLI показывает хеширование (МиБ), стадию чтения и подготовки отношений,
счётчик кандидатов и найденных геометрий, затем растеризацию. При долгой стадии
печатается время с последнего обновления; это не оценка процента выполнения.
Pyosmium по-прежнему читает региональный файл целиком, включая предварительный
проход по отношениям и индекс узлов. Нерелевантные отношения фильтруются до
сборки площадей; узлы и пути фильтруются по типу и тегам до передачи в Python.
По умолчанию используется 4 потока декодирования и очередь из 4 буферов;
при высокой загрузке CPU можно добавить `--threads 2`. Это не ограничение RAM
индекса. Ctrl+C прерывает импорт. Для готового окна повторно используйте TIFF.

Для множества участков одного города эффективнее один раз вырезать PBF города
с запасом, затем импортировать из меньшего файла. Если уже есть WSL и osmium-tool,
пример команды в WSL (не обязательная зависимость приложения):

```bash
osmium extract --strategy smart --bbox 39.55,54.48,39.90,54.78 /mnt/c/Projects/urban-development-generator/storage/imports/central-fed-district-latest.osm.pbf -o /mnt/c/Projects/urban-generator/ryazan-city.osm.pbf
```

После этого в исходной команде укажите `ryazan-city.osm.pbf`. Запас вокруг города
важен: извлечение osmium по узлам может не захватить объекты, пересекающие или
охватывающие окно без единого узла в области вырезки. Проверяйте полноту карты.
Переход на небольшой PBF не меняет правила классификации. Скорость и память
на исходном региональном файле Windows ещё не измерены.

## Правила классов, версия 2

- 0: ячейки без распознанного ограничения. Это **не** разрешение строительства.
- 1: известные запреты — вода и водотоки, железные дороги, леса, парки,
  поля, кладбища, промышленные/коммерческие и другие выбранные зоны,
  школы/социальные объекты и некоторые иные теги (см. urban/osm_import.py).
  Точечная школа защищает только свою ячейку; неизвестная граница не восстанавливается.
- 2: выбранные типы автомобильных дорог. Мосты, тоннели, непубличные и прочие
  highway консервативно защищаются кодом 1. Проект не строит полноценный
  пешеходный граф OSM, не моделирует развязки или ширины проезжей части.
- 3: контуры зданий и building:part, включая multipolygon.
- 255: NoData (объявлен, но прямоугольное окно заполнено классами 0–3).
  Наличие покрытия выгрузки и полнота OSM не установлены автоматически.

Пересечения: здания > запреты > дороги > 0. Растеризация all_touched
консервативно сохраняет тонкие объекты, но может разрывать дороги и увеличивать
их ширину. Локальная метрическая UTM по центру, квадратный пиксель без поворота.
Геометрии, пересекающие окно по bounding box, сохраняются; Rasterio ограничивает
их границами растра. Ошибки построения геометрий считаются по всему скану.
Подготовленный вход проверяет тот же read_terrain, что и интерфейс.

## Ограничения и лицензия

Исходные данные © OpenStreetMap contributors, https://www.openstreetmap.org/copyright
(ODbL). Атрибуция и SHA-256 PBF находятся в TIFF и JSON. При публикации карт
и производных данных сохранять атрибуцию и учитывать условия ODbL.
Экспорт хранит SHA входного TIFF и переносит OSM-метаданные в
`metrics.json.source` и теги `OSM_IMPORT`/`ATTRIBUTION` итогового TIFF.
SHA-256 исходного PBF указан отдельно в `source.source_sha256`.
Это работает и для подготовленного CLI-файла, открытого через «Свой TIFF».

Нет данных кадастра, нормативных отступов, охранных зон, рельефа и свободных
мест существующих школ; незаполненные OSM ячейки нельзя принимать за юридически
доступную землю. Пользователь проверяет исходную карту. Алгоритм MVP,
размер участка, визуализация и школьная модель не изменены.

## Проверки

```bash
uv run --frozen pytest -q
uv run --frozen --with osmium==4.3.2 pytest -q tests/test_osm_import.py
uv run --frozen --with osmium==4.3.2 pytest -q tests/test_osm_cache.py tests/test_osm_app.py
```

Тест формирует реальный маленький PBF из синтетических объектов и проверяет
дороги, здание, парк, водный multipolygon с отверстием, точку школы,
геопривязку и сохранность исходных классов при генерации.
Дополнительно проверяются путь из формы до ZIP, повтор из нового сеанса,
разные окна/файлы/версии, испорченный и прерванный кэш, перенос атрибуции,
отсутствие зависимости и сохранение прежнего проекта при ошибке и остановке.
На 835 МБ и Windows проверки не выполнены: исходный файл и ноутбук недоступны.
AppTest проверяет форму без настоящего браузерного прогона.
