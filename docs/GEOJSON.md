# Загрузка участка из GeoJSON

Запусти приложение по README, выбери **GeoJSON**. Скачай пример в форме либо
возьми [examples/site.geojson](../examples/site.geojson). Загрузи его, оставь
шаг 10 м, проверь предпросмотр, CRS, размер и площади. Подтверди легенду и
масштаб, нажми «Сгенерировать». Предварительный TIFF создавать не требуется.

Для примера при параметрах по умолчанию и seed 42: сетка 80×64, площадь
исследования 500000 м², 19 новых домов, 608 жителей, спрос 76 мест,
обслужено 64, дефицит 12. Это синтетический участок, а не данные города.

Формат — один UTF-8 FeatureCollection в WGS84 (EPSG:4326), координаты
`[долгота, широта]`. Старое поле `crs`, высота и неизвестные роли отклоняются.
Максимум 8 МиБ. В каждом Feature обязательна `properties.role`:

| role | Геометрия | Содержание |
|---|---|---|
| boundary | Polygon / MultiPolygon | Ровно одна граница территории анализа, отверстия допустимы |
| road | LineString / MultiLineString | Существующие дорожные оси |
| building | Polygon / MultiPolygon | Существующие здания |
| exclusion | Polygon / MultiPolygon | Вода и другие запреты строительства |

Например, дорожный объект внутри `features`:

```json
{
  "type": "Feature",
  "id": "street-1",
  "properties": {"role": "road", "source": "Мои проверенные данные"},
  "geometry": {"type": "LineString", "coordinates": [[39.001, 51.660], [39.001, 51.666]]}
}
```

Кольца полигонов замкнуты и не самопересекаются; отверстия лежат внутри
внешнего кольца, не пересекаются и не касаются. Для ограничения времени
проверки в одном Polygon допускается до 2048 точек с учётом отверстий;
контуры большей сложности упрости в GIS. Feature.id — уникальная строка
или целое число. Пропущенный ID становится `feature-N` по позиции в массиве,
поэтому явные ID предпочтительны. Необязательный `properties.source`
фиксирует происхождение; иначе записывается имя файла. Исходные свойства
и геометрии сохраняются целиком.

По центру охвата границы выбирается местная метрическая UTM, допустимы
широты −80…84°. Участки через линию перемены дат не поддерживаются.
Левый край сетки округляется вниз, верхний вверх до кратного шагу метра;
ширина и высота — вверх до целой ячейки. Полученные размеры показываются
до генерации. Максимум 256×256, шаг 5–10 м: для большего охвата уменьши
boundary либо увеличь шаг. Увеличение шага также уменьшает точность.

Граница и её отверстия учитываются по центрам ячеек. Дороги, запреты и
здания растеризуются с `all_touched=True`, после чего обрезаются границей.
Приоритет совпадает с OSM: здания > запреты > дороги > свободная земля.
На месте пересечения запрет может разорвать дорогу. Импорт не исправляет
топологию, мосты и диагональные соединения автоматически. Хотя бы одна
дорожная ячейка должна остаться внутри границы после приоритетов.
Неописанная территория внутри boundary — код 0; фактическую доступность
строительства подтверждает пользователь. Точность границы ограничена сеткой.

В ZIP остаются `result.tif`, `metrics.json`, `buildings.csv` и дополнительно
`source.geojson` — побайтный оригинал. В `metrics.json.source` указаны имя,
SHA-256 оригинала, версия и правила импорта, исходная CRS, ID/роли/источники
объектов. Основные CRS, transform, шаг и размеры описывают расчётную сетку.
Изменение шага сбрасывает подтверждения и прежний проект. Один исходник,
шаг, сценарий и seed воспроизводят классы, дома, метрики и ZIP.

Через ядро:

```python
from pathlib import Path
from urban.vector_import import read_geojson

terrain = read_geojson(Path("examples/site.geojson").read_bytes(), 10,
                       source_name="site.geojson")
```

Контрольный TIFF `tests/data/site-equivalent.tif` подготовлен независимо от
импортёра: EPSG:32637, верхний левый угол (500000, 5723640), 80×64, 10 м.
Классы заданы вручную по индексам (от нуля): свободная земля 0; дорога —
столбец 6 и строка 20; запрет — столбцы 60–62; здание — строки и столбцы
10–12; NoData — строки 28–37 и столбцы 32–43. Приоритеты применяются именно
в этом порядке. Векторные внешние границы смещены на 3 м внутрь сетки,
отверстие лежит на линиях сетки; координаты исходно заданы в этой UTM и
переведены в WGS84. Это позволяет проверить растеризацию независимо от
повторного использования той же функции.

```bash
uv run --frozen pytest -q tests/test_vector_import.py
uv run --frozen pytest -q
```

Тесты проверяют равенство двух входов при seed 42/43/44, отверстие,
приоритеты, происхождение, неизменность оригинала, детерминированный ZIP,
неверные роли/геометрии/размеры, отсутствие дороги и обычный локальный TIFF.
Streamlit AppTest проходит основную форму от загрузки до ZIP. Ручной прогон
в браузере на Windows и реальный городской GeoJSON этим тестом не заменяются.
