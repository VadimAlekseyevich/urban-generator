# Открытие проектных объектов в GIS (#64)

Скачай штатный ZIP завершённого расчёта и распакуй его. Помимо `result.tif`,
`metrics.json` и `buildings.csv` теперь есть `objects.csv` и пространственный
файл. Схема экспорта — версия 2, алгоритм генерации — по-прежнему версия 1.

| Вход | Пространственный файл | Система координат |
|---|---|---|
| GeoTIFF, GeoJSON, подготовленное окно OSM | project.geojson | WGS84, долгота/широта, EPSG:4326 |
| TIFF в локальном режиме | project-local-wkt.csv | Локальные метры, начало в левом нижнем углу; CRS отсутствует |

`objects.csv` содержит одну строку на пространственный объект. `object_id`
совпадает с `Feature.id` и `properties.object_id` в GeoJSON либо с ключом
строки CSV/WKT. В `buildings.csv` добавлен такой же `object_id`, числовой
`id` дома сохранён. Школы в `metrics.json.schools` также получили этот ключ.

| role | object_id | Представление |
|---|---|---|
| new_road | road-N | Полигон связного компонента **ячеек** новых улиц, с отверстиями |
| new_building | house-N | Пятно дома 2×2 ячейки |
| new_school | school-N | Одна условная ячейка школьной площадки |

Улицы не являются осевыми линиями. `representation=raster_cells` фиксирует
это явно, а `cell_count` и `area_m2` позволяют сверить площадь. Геометрия
школы обозначает условную площадку модели, не реальный контур здания.
Исходные объекты остаются в `result.tif`; пространственный файл содержит
только новые объекты. Дом имеет `building_id`, жителей, этажность, спрос
и обслуженные места. Школа — `school_id`, вместимость и занятые места.
Общая таблица содержит применимые поля; неприменимые поля пусты.

В GeoJSON геометрии переведены из метрической сетки в WGS84. Площади
`area_m2` рассчитаны в исходной метрической CRS, а не по градусам.
Поле `urban_generator` содержит хеш входа, происхождение, параметры,
метрики и описание пространственного экспорта. Для OSM сохраняются
атрибуция и отдельный SHA исходного PBF. Оригинал входного GeoJSON
по-прежнему находится в `source.geojson`.

Для локального TIFF не создаётся GeoJSON с фиктивными географическими
координатами. В QGIS открой `project-local-wkt.csv` как текстовый слой:
формат CSV, геометрия **WKT**, поле **WKT**, локальная/неопределённая CRS.
Координаты выражены в метрах; не назначай этому слою EPSG:4326 или UTM
без настоящей геопривязки. Параметры начала и единицы записаны в
`metrics.json.spatial_export`. CSV/WKT дублирует атрибуты `objects.csv`
для удобства открытия одним слоем.

Пустой проект даёт пустой FeatureCollection или CSV/WKT с заголовком,
нулевые счётчики и пустую таблицу объектов. Повтор того же расчёта
воспроизводит файлы и порядок ID. Перед выдачей ZIP заново выполняется
независимая проверка проекта; испорченный результат не экспортируется.

Проверки:

```bash
uv run --frozen pytest -q tests/test_gis_export.py tests/test_export.py
```

При наличии GDAL CLI тесты открывают оба формата через `ogrinfo`,
перепроецируют GeoJSON через `ogr2ogr`, проверяют известный угол дома
и восстанавливают маску новых улиц из прочитанной геометрии. В отдельном
GIS CI GDAL CLI обязателен. Приложение для экспорта использует только
Rasterio, NumPy и стандартную библиотеку Python; GDAL CLI нужен тестам.
