# Граница освоения отдельно от территории анализа (#50)

В разделе «Граница освоения (необязательно)» загрузи один полигон разрешённого
освоения с `properties.role=boundary`. Внешняя территория остаётся частью
анализа: существующие дороги снаружи сохраняются и доступны для маршрутов.
Новые улицы, пятна домов и площадки школ разрешены только внутри границы,
на исходной свободной земле. Вода, здания и NoData также остаются запретами.

Для GeoTIFF, GeoJSON и подготовленного OSM нужен GeoJSON FeatureCollection
WGS84 с одним Feature (Polygon/MultiPolygon). Поддерживаются вогнутые контуры
и отверстия. [Пример для demo.tif](../examples/development-boundary.geojson).
В свойствах можно указать `source`; по умолчанию это «Автор сценария».
Приложение не считает пользовательскую границу подтверждённым кадастровым
или нормативным ограничением: источник явно указан в отчёте.

Для локального TIFF координаты задаются в метрах от левого нижнего угла
карты. Это локальный JSON, не географический GeoJSON; обязательны маркеры
единиц. Например, прямоугольник 20–300 м по обеим осям:

```json
{
  "type": "FeatureCollection",
  "coordinate_mode": "local",
  "coordinate_unit": "m",
  "features": [{
    "type": "Feature",
    "properties": {"role": "boundary", "source": "Автор сценария"},
    "geometry": {"type": "Polygon", "coordinates": [
      [[20,20],[300,20],[300,300],[20,300],[20,20]]
    ]}
  }]
}
```

Ограничения файла и геометрии те же, что у GeoJSON-входа: до 8 МиБ,
замкнутые кольца без самопересечений, отверстия внутри внешнего контура,
не касаются и не пересекаются; до 2048 точек в одном полигоне.
Локальные координаты ограничены ±10 миллионами метров для отсечения
ошибочных единиц и численно непригодных значений.
WGS84-граница проецируется в CRS расчётной сетки. Контур на карте жёлтый;
показаны площадь пригодной свободной земли и её доля от всей исходной
свободной земли. Область за территорией анализа автоматически исключается.

Правило консервативное: ячейки, которых касается внешний контур или контур
отверстия, исключаются целиком. Проверяется не только центр ячейки, поэтому
маленькое отверстие внутри одной ячейки также запрещает её. Это может
уменьшить доступную площадь примерно на полосу одного шага у границы.
Размер пятна дома и условная школьная ячейка не могут пересечь контур.
Показатель освоения свободной земли по-прежнему относится ко всей исходной
свободной площади; пригодная доля показана отдельно.

Изменение или удаление файла сбрасывает подтверждения, текущий расчёт,
сравнение и выбор на карте. При смене основного входа или шага файл
границы очищается. Без дополнительного файла действует прежний контракт.
Пустая разрешённая область корректна: прирост 0, полный недобор и
пояснение об отсутствии пригодных ячеек. Удаление границы возвращает
исходную область расчёта после нового подтверждения и генерации.

В ZIP дополнительно записан побайтный оригинал `development-boundary.json`.
`metrics.json.development_area` хранит источник, SHA-256, единицы, версию
правил, проецированную геометрию и пригодную площадь. Эти сведения также
переходят в GeoJSON пространственного экспорта. SHA основного входа
сохраняет прежний смысл; у файла границы собственный SHA.

```bash
uv run --frozen pytest -q tests/test_development.py
```

Контрольная карта содержит вогнутую область, два отверстия (включая меньше
ячейки), внешний коридор исходной дороги и запретную полосу. Проверяются
геометрия всех новых ячеек, связность, сохранность исходника, пустой
результат, сброс через форму и независимое отклонение проекта с объектами
за границей. Реальные кадастровые границы и Windows вручную не проверены.
